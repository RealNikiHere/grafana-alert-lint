## 🔴 Критичное

### A01. GAL007 по `title` — ложная ошибка на Grafana ≥ 11.6

Grafana **убрала** ограничение уникальности `title` в PR
[grafana/grafana#102067](https://github.com/grafana/grafana/pull/102067)
(вмержен 2025-03, milestone **11.6.x**): «Now rule title can be the same for
alert rules in the same folder\group». Мотивация — миграция Prometheus-правил,
где имя уникально только внутри группы.

Линтер по-прежнему выдаёт `error GAL007` на повтор `title` в группе, то есть
**валит CI на валидном для Grafana 11.6+ провижининге**. На сервере владельца
стоит `grafana/grafana:13.3.0` (`niki-server/metrics/compose.yml:68`) — то есть
целевая версия уже после снятия ограничения.

Проверка (одна группа, один `title` дважды — Grafana 11.6+ это примет):

```bash
mkdir -p "$TMPDIR/a01" && cd "$TMPDIR/a01" && cat > dup-title.yml <<'EOF'
apiVersion: 1
groups:
  - orgId: 1
    name: g
    folder: F
    interval: 1m
    rules:
      - {uid: a, title: Disk full, condition: C, for: 5m, noDataState: OK,
         execErrState: Error, labels: {severity: crit}, annotations: {summary: s},
         data: [{refId: A, model: {expr: up}}, {refId: C, model: {type: threshold, expression: A}}]}
      - {uid: b, title: Disk full, condition: C, for: 5m, noDataState: OK,
         execErrState: Error, labels: {severity: crit}, annotations: {summary: s},
         data: [{refId: A, model: {expr: up}}, {refId: C, model: {type: threshold, expression: A}}]}
EOF
galint dup-title.yml   # сейчас: error GAL007, rc=1
```

Что делать: перевести дубль `title` из `error` в `warning` (и сказать в
README, что до 11.5 это действительно ошибка), либо оставить ошибкой, но под
флагом/настройкой версии Grafana.

## 🟡 Важное

### A02. GAL007 по `uid` — уникальность в Grafana не глобальная, а в пределах org

В `LintState.uids` ключ — только `uid`, без `orgId`. Провижининг-файл может
содержать группы разных организаций (`orgId: 1`, `orgId: 2`), и одинаковый
`uid` в разных org легален. Линтер выдаёт `GAL007` и `rc=1`. Проверено: файл
с `uid: dup` в `orgId: 1` и `orgId: 2` даёт 2 находки GAL007.

Заодно неверна формулировка в docstring `LintState` и в README — «Grafana
требует глобальной уникальности uid»: уникальность ограничена org.

### A03. GAL007 по `title` — неверное пространство имён даже для Grafana ≤ 11.5

До 11.6 ограничение было на **(org, folder, title)** — ошибка Grafana:
«rule title under the same organisation and folder should be unique». Линтер
же ключует `(group_name, title)` и вообще не читает `folder`. Следствия, оба
проверены:

1. **Ложный минус:** один `folder`, один `title`, разные группы → `0 находок`,
   а Grafana 11.5 и ниже такой провижининг отвергнет.
2. **Ложный плюс:** разные `folder` (например `a/` и `b/`), одинаковое имя
   группы `node` и одинаковый `title` → `GAL007`, хотя Grafana это принимает.

Исправление: читать `group.get("folder")` и `group.get("orgId")`, ключ —
`(orgId, folder, title)`; для `uid` — `(orgId, uid)`. Тогда A02 и A03
закрываются одним изменением.

### A04. `--max-file-size` с отрицательным значением превращает все файлы в ошибки

`argparse type=int` без проверки: `galint rules/ --max-file-size -1` даёт
«файл … больше лимита -1» для каждого файла, `rc=2`. Проверено.

Исправление: валидатор `type=` с отказом на `< 0` (или трактовать `< 0` как
«без лимита», но тогда молча — хуже).

### A05. Пример вывода в README не воспроизводится

README (`## galint — линтер…`, блок `console`) показывает, что
`galint metrics/grafana/provisioning/alerting/` выдаёт `error GAL001` на
`up{job="node"} == 0`. Фактический прогон по этому пути — **0 находок**: в
`alert-rules.yml` правило переведено на threshold-выражение `B`
(`up{job="node"}` без сравнения). То есть первый экран README показывает
вывод, которого пользователь не получит.

Исправление: показывать вывод на `tests/fixtures/regression-0003.yml` (он
ровно это и делает) и указать этот путь в команде.

## 🟡 Среднее

### A06. Невалидный `interval` группы молча считается 60 секундами

`interval: jedes Mal` → `parse_duration` → `None` → подстановка 60 с, GAL011
печатает «короче интервала группы (60s)», хотя в файле написано другое.
Проверено. Лучше: отдельная находка «interval не разбирается» (иначе линтер
молча врёт про причину).

### A07. `for: 0` числом считается корректной длительностью

`parse_duration(0)` → `0.0`, поэтому `GAL004` молчит. Grafana ждёт строку
(`0s`); числовой `for` API, скорее всего, отвергнет. `[предположение]` —
нужна проверка на живом Grafana. Побочно: условие
`raw_for == 0 and not isinstance(raw_for, bool)` в `lint_rule` недостижимо —
`parse_duration(0)` уже не `None`.

### A08. Версия пакета в двух местах

`pyproject.toml: version = "0.1.0"` и `src/grafana_alert_lint/__init__.py:
__version__ = "0.1.0"`. `publish.yml` сверяет тег только с `pyproject.toml`,
поэтому `galint --version` может соврать. Источник истины — один:
`importlib.metadata.version("grafana-alert-lint")`.

### A09. CI не собирает пакет

`ci.yml` гоняет ruff/pytest/фикстуры, но не `python -m build` + `twine check`.
Поломка упаковки (MANIFEST, метаданные, лицензия в wheel) обнаружится только
на теге, в `publish.yml`. Сборка стоит секунды — её место в CI на PR.
Там же: нет Python 3.14 в матрице при открытом `requires-python = ">=3.10"`,
нет `ruff format --check .`.

### A10. Тег `v*` с любой ветки публикует релиз

`publish.yml` реагирует на `push: tags: v*`, не проверяя, что коммит есть в
`main`. Достаточно тега на боковой ветке (или на чужом форке с правом пуша
тега). Добавить `git merge-base --is-ancestor HEAD origin/main` (после
`fetch-depth: 0`) или `github.ref_protected`.

### A11. Мусор в корне проекта

`.probe/` (4 файла) и `.probe2/` (3 файла) — незакоммиченные пробы, в
`.gitignore` их нет. По правилам воркспейса временное живёт в `$TMPDIR`.
Удалить или дописать в `.gitignore`.

### A12. `dist/` собран до последней правки и до будущих исправлений

`dist/*` соответствует `08136af`, но рабочее дерево изменено (`cli.py`,
`README.md`, `CHANGELOG.md`). Перед публикацией — пересобрать и заново
прогнать `twine check`. Каталог в `.gitignore`, вреда нет, но артефакт
устарел.
