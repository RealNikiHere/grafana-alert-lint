## [0.1.0] — 2026-11-24

Первая версия. Ничего не публиковалось, поэтому раздел «Unreleased» не нужен.

### Добавлено

- 13 кодов (GAL001–GAL013) для провижиненных правил алертов Grafana:
  фильтрующее сравнение при `noDataState: Alerting`, `NoData`, отсутствие
  или неизвестное `noDataState`, `for`, `<` в аннотациях (Telegram `400`),
  `condition`, дубли `uid`/`title`, `severity`, `summary`, `execErrState`,
  `for` короче интервала группы, отсутствие идентичности правила.
- CLI `galint` с `--format text|json`, `--strict`, разворотом каталогов.
- Общее состояние уникальности `uid`/`title` на весь запуск: дубли ловятся
  между документами и файлами, а не только внутри одного.
- Тесты на каждую проверку и на каждый найденный аудитом дефект
  (`pytest`), `ruff`, CI на Python 3.10–3.14, workflow публикации в PyPI
  через OIDC Trusted Publishing с PEP 740 attestations.
- Лицензия Apache-2.0.

### Исправлено до релиза (по итогам аудита)

- `KeepLast` принимается как валидное значение `noDataState` и `execErrState`;
  `noDataState: Error` — отвергается.
- GAL001 больше не срабатывает на `==`/`!=` внутри матчеров лейблов
  и игнорирует сравнения с `bool`; зато ловит `>`, `<`, `>=`, `<=`.
- GAL005 проверяет только `<`: `>` в тексте Telegram не ломает.
- Duplicate `uid` ловится для числовых значений и между файлами.
- GAL006 срабатывает, когда `condition` есть, а `data` пуст.
- `parse_duration` понимает `ms`, `s`, `m`, `h`, `d`, `w`, `y` — только целые
  части, как `model.ParseDuration` в Grafana (`1.5s` отвергается);
  при отсутствии `interval` группы считается 1 минута.
- CLI не теряет находки, если один из путей не прочитался; в JSON-отчёте
  появилось поле `path_errors`.
- CI-шаг «регрессия должна падать» больше не ломается из-за `pipefail`.

### Исправлено до релиза (по итогам аудитов)

- Скаляр в позиции списка (`groups: 5`, `rules: 5`, `data: 5`) больше не
  роняет линтер трейсбеком: проверяется `isinstance(..., list)`.
- Файл в недекодируемой кодировке (`UnicodeDecodeError`) превращается в
  штатную ошибку чтения с кодом `2`, а не в падение на весь запуск.
- Один и тот же файл, переданный дважды (каталог + путь внутри, повтор пути),
  проверяется один раз — раньше это давало ложный GAL007.
- Каталог без прав на чтение — ошибка (`2`), а не «чисто»: раньше CI на таком
  каталоге молча показывал ноль находок.
- PromQL raw-строки в backtick (`up{note=`a}b == c`}`) не считаются
  сравнением.
- Сообщение GAL001 переформулировано: сравнение может и отбрасывать серии,
  и оставлять только аварийные — линтер не угадывает «здоровое» значение
  и просит проверить порог живьём.
- `publish.yml`: проверка «тег совпадает с версией в `pyproject.toml`»,
  прогон `ruff` и `pytest` до сборки, `twine check`, OIDC-права только у
  job `publish`, attestations; ручной запуск с ветки убран.
- `MANIFEST.in` — `CHANGELOG.md` и тесты с фикстурами попадают в sdist;
  `dependabot.yml` для pip и GitHub Actions.
- Глубоко вложенный YAML (`RecursionError` от PyYAML) и документы длиннее
  одного читаются без падения: документы разбираются по одному, ошибка
  становится штатной ошибкой чтения с кодом `2`.

### Исправлено до релиза (по итогам пятого аудита)

- GAL007 ловил дубли не в тех границах: `uid` сравнивался глобально, хотя
  Grafana требует уникальности только в пределах организации, а `title` — в
  пределах группы, хотя он уникален для (организация, папка). Теперь ключи
  `(orgId, uid)` и `(orgId, folder, title)`; одинаковые `uid` в разных `orgId`
  и одинаковые `title` в разных папках больше не дают находок.
- Дубль `title` стал предупреждением: Grafana 11.6 (PR #102067) сняла это
  ограничение, и CI на валидном провижининге больше не падает из-за него.
- Вкусовые проверки (GAL002, GAL004, GAL008, GAL009, GAL010, GAL011) по
  умолчанию молчат и включаются `--opinionated`: на чужом репозитории они
  давали десятки предупреждений, в которых терялась настоящая находка.
- `interval` группы, который не разбирается как длительность Grafana, теперь
  даёт GAL013 (`error`), а не молчаливое «60s».
- `--max-file-size` принимает только неотрицательные целые: раньше `-1`
  превращал каждый файл в «больше лимита -1» с кодом 2.
- Непарный суррогат в YAML (`uid: "a\ud800"`) больше не роняет печать
  трейсбеком `UnicodeEncodeError`: потоки вывода настраиваются с
  `errors="backslashreplace"`.
- Огромное число в `interval` или `for` (сотни цифр) больше не даёт
  «внутренняя ошибка OverflowError» с потерей всех находок файла: значение
  считается неразбираемым (`GAL013`/`GAL004`).
- Дробные длительности (`1.5s`) больше не считаются валидными: Grafana
  (`model.ParseDuration`) принимает только целые части.
- `orgId: 1.0`, `1` и `"1"` — одна организация (раньше дубль `uid` между
  `1.0` и `1` пропускался).
- `title` recording rules тоже занимает имя в папке: дубль `title` между
  recording и alert-правилом теперь даёт GAL007.
- Версия пакета — один источник (`grafana_alert_lint.__version__`), pyproject
  берёт её динамически; `publish.yml` сверяет тег с ней, а не с копией в
  `pyproject.toml`. Добавлен `python -m grafana_alert_lint`.
- Пример вывода в README теперь воспроизводим (`tests/fixtures/regression-0003.yml`):
  прежний путь после перевода правила на threshold давал ноль находок.
- CI собирает sdist и wheel, гоняет `twine check --strict`, проверяет состав
  wheel (все модули на месте), установку wheel в чистый venv и тесты из
  распакованного sdist на каждом PR; в матрицу добавлен Python 3.14, в линт —
  `ruff format --check`. `publish.yml` отказывается публиковать тег, который
  стоит не на коммите из `main`.

### Исправлено до релиза (по итогам третьего аудита)

- Словари и списки в скалярных полях YAML (`noDataState`, `execErrState`,
  `refId`, `model.type`, `labels.severity`, `annotations.summary`,
  `condition`) больше не дают `TypeError: unhashable type`: такое значение
  считается невалидным и попадает в находку, а не в трейсбек.
- GAL007 больше не путает `uid` одного правила с `title` другого: проверка
  `title` идёт по самому `title`, а не по «title или uid».
- `uid: 0`, `uid: ""`, `for: false`, `for: [..]` — корректные сообщения
  вместо молчания или ложного GAL012.
- Находки из уже разобранных документов файла не теряются, если в следующем
  документе битый YAML: они печатаются, файл при этом даёт код `2`.
- Страховка в CLI: любое неожиданное исключение по файлу становится ошибкой
  чтения с кодом `2`, а не трейсбеком на весь запуск.
- `--max-file-size` (по умолчанию 4 МиБ, `0` — без лимита): разбор YAML
  раздувает память в 70-80 раз, файл на 30 МБ давал ~2.3 ГБ RSS.
- `publish.yml`: права `contents: read` у job `publish` (права job заменяют
  права workflow), `SOURCE_DATE_EPOCH` для воспроизводимой сборки.
- `[project.urls]`: добавлены Repository, Issues, Changelog.
- При обходе каталога линтуются только обычные файлы: FIFO и симлинк на
  устройство (`/dev/zero`) больше не вешают чтение навсегда.
- Grafana-managed recording rules (`record:` в элементе группы) пропускаются:
  у них нет `condition`/`noDataState`, и проверки алертов к ним неприменимы.
- Сообщение GAL001 больше не утверждает, что результат обязательно пуст на
  здоровом состоянии: у «алертов на отсутствие» (`sum(up) < 1` с
  `noDataState: Alerting`) это осознанный приём. Добавлен флаг
  `--ignore CODE[,CODE]`, чтобы не считать такие находки ошибками.
- Лимит размера по умолчанию снижен до 4 МиБ: 30 МБ файла — это ~2 ГБ RSS,
  и прежние 32 МБ отсекали только то, что уже роняет процесс.
